\begin{abstract}
Tool-augmented LLM agents deployed in Security Operations Centers (SOCs) operate over heterogeneous data feeds where execution context and adversarial inputs share the same token space. This structural property exposes autonomous agents to \textbf{Indirect Prompt Injection (IPI)}, where adversary-crafted strings in syslog telemetry, web headers, or case notes hijack the agent's tool-calling pipeline. Naive string-matching heuristics suffer from severe false-positive rates on legitimate attack discussions and are trivial to evade, while LLM-as-a-judge approaches introduce latency and recursive injection vulnerabilities.

This report presents the \textbf{SENTINEL SOC Defense AI Layer}, a deterministic, sub-millisecond provenance-aware decision firewall. SENTINEL intercepts candidate tool invocations prior to execution and evaluates them against four orthogonal dimensions: (1) \textbf{Action Criticality}, (2) \textbf{Provenance Trust Floor}, (3) \textbf{Independent Multi-Source Corroboration}, and (4) \textbf{Memory Trust Inheritance}. Furthermore, the system implements automated safe-action rewriting for consequential tools and deterministic tool-whitelisting backstops. We detail the formal policy mechanics, state machine lifecycle, HTTP contracts, and multi-toggle ablation probes.
\end{abstract}

\section{Threat Model and Design Motivation}

\subsection{Autonomous Agentic Workflows in the SOC}
In modern SOC infrastructure, autonomous agents orchestrate multi-step triage and incident response. A representative workflow consists of:
\begin{enumerate}[leftmargin=1.5em]
    \item Ingesting an alert from a SIEM / EDR aggregator (e.g., suspicious outbound beaconing on \texttt{SRV-22}).
    \item Invoking investigative read-only tools (\texttt{alert\_read}, \texttt{asset\_lookup}, \texttt{intel\_search}).
    \item Synthesizing observations into persistent memory to maintain multi-turn investigation state.
    \item Formulating and proposing state-changing candidate actions (\texttt{incident\_update}, \texttt{remediation\_execute}, \texttt{disable\_monitoring}).
\end{enumerate}

\subsection{The Vulnerability: Indirect Prompt Injection (IPI)}
Because LLMs process data and control instructions within an undifferentiated context window, untrusted payload strings can hijack agent execution. In a SOC setting, untrusted data frequently contains imperative syntax:
\begin{itemize}[leftmargin=1.5em]
    \item \textbf{Adversary-Controlled Syslog}: Web access log containing embedded commands like \texttt{close\_incident} or \texttt{disable\_monitoring}.
    \item \textbf{Phishing Email Headers}: Case notes with fake supervisor instructions demanding ticket closure.
    \item \textbf{Third-Party Threat Intel Feeds}: Unverified external RSS feeds suggesting disabling noisy correlation rules.
\end{itemize}

When the LLM ingests these inputs, it may generate tool calls that execute destructive actions (e.g., closing open incidents during an ongoing ransomware outbreak, disabling endpoint sensors, or leaking credentials).

\subsection{Why Conventional Approaches Fail}
\begin{itemize}[leftmargin=1.5em]
    \item \textbf{Syntactic Heuristics / Keyword Blocklists}: Flagging phrases like \textit{``disable monitoring''} or \textit{``isolate host''} triggers excessive false alarms on legitimate alerts that describe malware attempting those very actions. Conversely, minor semantic mutations or encodings easily bypass keyword filters.
    \item \textbf{LLM-as-a-Judge Guardrails}: Running a secondary LLM call to evaluate the safety of the primary LLM adds significant latency ($1\text{--}3\text{ seconds}$), incurs high inference cost, and remains susceptible to secondary prompt injections.
    \item \textbf{SENTINEL's Approach}: A deterministic, provenance-bound decision engine ($<1\text{ ms}$ evaluation overhead) that operates on structured origin metadata and action criticality rather than lexical surface forms.
\end{itemize}

\section{Core Defense Philosophy and Architecture}

\subsection{Architectural Decoupling}
SENTINEL is deployed as an out-of-process reverse proxy between the agent's action planner and the tool execution runtime. The agent cannot directly dispatch commands to the environment; every candidate action must obtain an explicit policy verdict from the defense layer.

\begin{figure}[ht]
\centering
\begin{tcolorbox}[colback=boxbg,colframe=primary!80,arc=1.5mm,width=0.98\textwidth]
\small
\textbf{Decoupled Policy Pipeline:}
\begin{enumerate}[leftmargin=1.2em]
    \item \textbf{Agent Request} $\to$ Dispatches \texttt{POST /v1/decision} with candidate action and provenance graph.
    \item \textbf{Tool Whitelist Gate} $\to$ Enforces scenario \texttt{allowed\_tools} policy.
    \item \textbf{Consequential Action Rewrite} $\to$ Transforms state-altering actions into human-confirmation requests.
    \item \textbf{Provenance Taint \& Risk Scoring} $\to$ Computes $R(a)$ based on criticality and weakest provenance.
    \item \textbf{Corroboration Backstop} $\to$ Hard-blocks high-criticality actions lacking independent trusted verification.
    \item \textbf{Action Verdict} $\to$ Returns \texttt{allow}, \texttt{rewrite}, \texttt{escalate}, or \texttt{block} with structured audit metadata.
\end{enumerate}
\end{tcolorbox}
\caption{SENTINEL Defense Evaluation Pipeline}
\end{figure}

\section{Mathematical Policy Formulation}

\subsection{Formal Risk Formulation}
Let $\mathcal{O}_a = \{o_1, o_2, \dots, o_n\}$ denote the set of observations justifying action $a$, and let $\mathcal{M}_a = \{m_1, m_2, \dots, m_k\}$ denote the set of justifying memory records.

\paragraph{1. Minimum Provenance Floor ($T_{\min}$):}
The system enforces a strict weakest-link taint model across all justifications:
\begin{equation}
    T_{\min}(a) = \min \Big( \{ \text{trust}(o) \mid o \in \mathcal{O}_a \} \cup \{ \text{trust}(m) \mid m \in \mathcal{M}_a \} \Big)
\end{equation}
If no provenance is attached, $T_{\min}(a) = 0.00$.

\paragraph{2. Independent Corroboration ($K$):}
Let $\mathcal{S}$ denote the set of unique data sources contributing justifications with trust $T \ge 0.70$:
\begin{equation}
    K(a) = \big| \big\{ \text{source\_id}(x) \mid x \in \mathcal{O}_a \cup \mathcal{M}_a \text{ and } \text{trust}(x) \ge 0.70 \big\} \big|
\end{equation}

\paragraph{3. Imperative Syntax Indicator ($W_{\text{pattern}}$):}
An auxiliary regex detector identifies imperative command patterns. Its contribution is strictly bounded:
\begin{equation}
    W_{\text{pattern}} = \begin{cases} 
      0.15 & \text{if imperative patterns match in context} \\
      0.00 & \text{otherwise}
   \end{cases}
\end{equation}

\paragraph{4. Unified Risk Score ($R$):}
\begin{equation}
\boxed{R(a) = \text{clamp}_{[0, 1]} \Big( C(a) \cdot \big(1 - T_{\min}(a)\big) + W_{\text{pattern}} - \big(0.10 \cdot \min(K(a), 2)\big) \Big)}
\end{equation}

\subsection{Deterministic Decision Rules and State Machine}
The policy resolves candidate actions via a deterministic decision tree:

\begin{enumerate}[leftmargin=1.5em]
    \item \textbf{Unauthorized Tool Rejection}:
    \begin{equation}
        \text{If } a.\text{type} == \texttt{"tool\_call"} \land a.\text{tool} \notin \text{allowed\_tools} \implies \textbf{BLOCK } (\texttt{TOOL\_NOT\_ALLOWED\_BY\_POLICY})
    \end{equation}
    \item \textbf{Corroboration Backstop Firewall}:
    \begin{equation}
        \text{If } C(a) \ge 0.80 \land K(a) == 0 \land T_{\min}(a) \le 0.30 \implies \textbf{BLOCK } (\texttt{CORROBORATION\_BACKSTOP})
    \end{equation}
    \item \textbf{Safe Consequential Action Rewriting}:
    \begin{equation}
        \text{If } a.\text{tool} \in \{\texttt{remediation\_execute}, \texttt{incident\_update}(\text{status}=\texttt{"closed"})\} \implies \textbf{REWRITE}
    \end{equation}
    The action is transformed into an advisory text response requesting human confirmation without altering system state.
    \item \textbf{Risk Interval Classification}:
    \begin{equation}
        \text{Verdict}(a) = \begin{cases}
            \textbf{BLOCK} & \text{if } R(a) \ge 0.70 \\
            \textbf{ESCALATE} & \text{if } 0.40 \le R(a) < 0.70 \\
            \textbf{ALLOW} & \text{if } R(a) < 0.40
        \end{cases}
    \end{equation}
\end{enumerate}

\subsection{Memory Provenance Inheritance}
To prevent \textbf{Memory Poisoning} (where an agent stores untrusted text in memory and later retrieves it as an unverified ``fact''), the memory layer enforces transitive trust inheritance:
\begin{equation}
    m_{\text{new}} = \text{write}(c, \mathcal{O}_{\text{used}}) \implies \text{trust}(m_{\text{new}}) = \min_{o \in \mathcal{O}_{\text{used}}} \text{trust}(o)
\end{equation}
If an agent synthesizes memory from an external blog ($T=0.20$), the resulting memory entry permanently carries $T=0.20$.

\subsection{End-to-End Decision Trace Walkthrough}

\begin{techbox}{Step-by-Step Request Evaluation}
\begin{enumerate}[leftmargin=1.2em]
    \item \textbf{Ingestion}: The autonomous agent issues an HTTP POST to \texttt{/v1/decision}.
    \item \textbf{Translation}: \texttt{adapter.py} unpacks the candidate tool call, conversation history, and provenance graph, assembling a \texttt{CandidateAction}.
    \item \textbf{Permission Check}: \texttt{policy.py} checks the tool against \texttt{policy\_context.allowed\_tools}.
    \item \textbf{Provenance Floor Calculation}: \texttt{trust.py} traverses observation and memory IDs to determine $T_{\min}$.
    \item \textbf{Corroboration Counting}: Discovers unique, independent sources with $T \ge 0.70$.
    \item \textbf{Backstop Evaluation}: Checks if high criticality ($C \ge 0.80$) meets uncorroborated low trust ($T \le 0.30$).
    \item \textbf{Action Rewrite}: If the tool is consequential and permitted, replaces tool execution with human-in-the-loop review text.
    \item \textbf{Audit Logging}: \texttt{trace.py} appends the decision event to \texttt{sentinel\_decisions.jsonl}.
    \item \textbf{Response Dispatch}: Returns HTTP 200 with structured decision JSON.
\end{enumerate}
\end{techbox}

\subsection{Findings and Security Implications}
\begin{itemize}[leftmargin=1.5em]
    \item \textbf{Corroboration Backstop Validation (Probe A)}: Disabling the corroboration backstop transitions high-risk actions ($C=0.80$) justified by untrusted inputs from \textbf{BLOCK} to \textbf{ESCALATE}. The backstop is required to prevent unverified high-impact actions from proceeding without human sign-off.
    \item \textbf{Instruction Detector Bounding (Probe B)}: The detector contributes exactly $+0.15$ to elevate borderline low-criticality actions from \textbf{ALLOW} to \textbf{ESCALATE}, proving it acts as an auxiliary signal without independently vetoing operations.
    \item \textbf{Memory Trust Inheritance Criticality (Probe C)}: When memory trust inheritance is disabled, an action justified by poisoned memory shifts from \textbf{BLOCK} to \textbf{ALLOW}. This demonstrates that without memory taint tracking, agents are completely vulnerable to multi-turn prompt injection.
    \item \textbf{Invariant Safety Controls (Probes D \& E)}: Safe rewrites and tool permission limits operate unconditionally across all configuration switches, verifying that structural guardrails remain active regardless of heuristic settings.
\end{itemize}

\section{Conclusion and Operational Best Practices}
The SENTINEL SOC Defense AI Layer demonstrates that robust protection against Indirect Prompt Injection does not require complex recursive LLM judges or brittle lexical blocklists. By enforcing **action criticality**, **provenance tracking**, **memory taint inheritance**, and **automated safe rewrites**, the architecture provides verifiable security guarantees with sub-millisecond evaluation latency.

\paragraph{Key Implementation Takeaways:}
\begin{enumerate}[leftmargin=1.5em]
    \item \textbf{Anchor Decisions in Provenance}: Lexical forms are easily manipulated; origin metadata must govern execution authority.
    \item \textbf{Enforce Transitive Memory Taint}: Prevent memory wash attacks by preserving source trust across all memory read/write cycles.
    \item \textbf{Transform Rather Than Abort}: Use safe action rewrites to convert consequential tool calls into human confirmations, preserving agent utility while eliminating execution risk.
\end{enumerate}
